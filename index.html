Creating Your First Website and Setting Up a Work Environment in GitHub

Step 1: Building Your First Web Page Locally

The very first step is to understand how a website works. For this reason, I want you to download folder MLL771-ENG611-Intro2DH and work from your own computers. To make your first website you only need a single folder on your computer, one HTML files, and a browser. That is all a web page really is. Download this folder, and save it on your Desktop or another location you will easily find it.

What Is This Folder?

Think of your project as a folder or a small library that lives on your desk. Right now, only you can open it. Your browser is the reader — when you open an index.html file, the browser reads it and displays it as a page, exactly like opening a book. No internet needed. No server in the cloud. Just your computer talking to itself.

📁 my-first-website/
    ├── index.html  ← the structure and content
    └── style.css   ← the colors and fonts (optional for now because the instructions are in the HTML head)

How Does CSS Connect to HTML?

Look at the <head> section at the top of this file. You will find a <style> block — that is where the CSS lives inside the HTML itself. The browser reads the <head> first, learns the visual rules, and then applies them as it renders the <body>.

For example, the CSS rule h1 { color: #bd5734; } tells the browser: "every time you see an <h1> tag, make the text that warm reddish-brown." The rule body { background-color: #e6e2d3; } sets the sandy background you are reading on right now.

💡 Try it: Open this file in a text editor, change #bd5734 to blue inside the h1 rule, save, and refresh your browser. You just edited a live design.

Your Task for Step 1

Now it is your turn. In the STEP1 folder, open index.html in your text editor and make it your own. This is still just your private folder — nothing goes online yet. Experiment freely.

✏️ Before moving to Step 2, make sure you have:

  • Replaced the <title> with your own name or project title
  • Changed at least one color in the CSS (background, heading, or paragraph). A list of color codes.
  • Added at least two <h1> or <h2> headings with your own text
  • Written content inside the <p> paragraphs
  • Included at least one link using <a href="...">
  • Added at least one image using <img src="...">

Step 2: Publishing Your Website on GitHub Pages

Now that your website works locally, it is time to put it online so anyone can visit it. Think of what we did in Step 1 as writing in your private notebook — now we are going to place that notebook on a public shelf. The files do not change at all. We are simply moving them to a place the rest of the world can reach.

We will use GitHub Pages, a free service that turns a GitHub repository directly into a live website. GitHub is normally used by programmers to store and share code, but for our purposes it works perfectly as a simple web host — and it is free.

What you need to do

Follow these three steps in order:

  1. Create a GitHub account. Go to github.com and sign up. Choose your username carefully because it will become part of your website's permanent address. A name like firstnamelastname works well and looks professional.
  2. Create a new repository named exactly username.github.io, replacing username with the username you just chose. The name must match your username exactly, including lowercase letters — otherwise GitHub Pages will not activate.
  3. Upload your files from Step 1 to the repository. You can drag and drop them directly on GitHub for now. In a later step we will learn how to do this with GitHub Desktop from your computer.
  4. Activate GitHub Pages. Go to your repository's Settings → Pages (left menu). Under Branch, select main and click Save.

⏱ Wait a moment. After saving, GitHub takes 1–2 minutes to build your site. Then visit https://username.github.io and your website is live.

🌐 What just happened? GitHub read your index.html file and started serving it as a real website. The same file your browser was opening from your Desktop is now being opened by browsers anywhere in the world. The library moved from your desk to a public shelf.

Step 3: Using a Jekyll Template — Academic Pages

So far you have built a website by writing HTML and CSS by hand. That is a great way to understand how the web works. But in practice, most websites are not built from scratch, they use templates. A template gives you a ready-made structure, design, and layout. You only need to replace the content with your own.

One of the most popular tools for this on GitHub Pages is Jekyll. Jekyll is a system that takes simple text files —written in a format called Markdown— and automatically converts them into a full website. You write your biography, your publications, your blog posts as plain text. Jekyll handles all the HTML and CSS for you.

The template we will use is called Academic Pages (github.com/academicpages), a widely used template designed specifically for researchers, professors, and students who want a clean professional site with sections for a biography, publications, teaching, and a blog. The goal here is not to master Jekyll — it is to understand that you can adopt an entire working website in minutes, and then simply replace the content with your own. If you prefer another template, check the the Jekyll free template list.

What you are about to do

You are going to take the Academic Pages template and make it yours. This means replacing everything currently in your username.github.io repository with the files from this template. Think of it as moving out of your hand-built house and into a fully furnished one — you just need to put your own belongings inside.

Step by step

  1. Go to the Academic Pages repository. Open github.com/academicpages/academicpages.github.io in your browser.
  2. Use the template. Click the green "Use this template" button at the top right, then select "Create a new repository". In the repository name field, type exactly username.github.io (using your own GitHub username). This will create a fresh copy of the template directly in your account — no manual downloading needed.
  3. Activate GitHub Pages. Go to your new repository's Settings → Pages. Under Branch, select main and click Save. After 1–2 minutes, your new site will be live at https://username.github.io.
  4. Make it yours — start with _config.yml. This is the most important file in the template. Open it in GitHub by clicking on it, then click the pencil icon to edit. Replace the placeholder values with your own: your name, your institution, a short description of yourself, and your URL. Commit the changes when done. This one file updates your name and description across the entire site automatically.
  5. Edit your biography. Go to the _pages/ folder and open about.md. This is your homepage text. It is written in Markdown — a very simple format where **bold** makes text bold and # Heading creates a heading. Replace the placeholder text with a short bio of yourself.
  6. Add or remove sections. The navigation menu is controlled by _data/navigation.yml. If you do not need a Publications or Teaching section yet, you can simply delete those lines from the file and they will disappear from your site.

📁 The key files to know in Academic Pages:

  _config.yml  ← your name, title, and site-wide settings
  _pages/about.md  ← your homepage biography
  _posts/  ← blog posts, each one a separate text file
  _data/navigation.yml  ← the navigation menu
  images/  ← your profile photo and other images

💡 What happened to HTML and CSS? They are still there — Jekyll generates them automatically from your text files every time you save a change. You do not need to touch them unless you want to customize the design deeply. This is exactly the point of a template: the structure is already built. Your job is to fill it with your content.

✏️ Before finishing Step 3, make sure you have:

  • Created your repository from the Academic Pages template
  • Confirmed the site is live at https://username.github.io
  • Edited _config.yml with your real name and description
  • Replaced the placeholder text in _pages/about.md with your own bio
  • Removed at least one section from the navigation that you do not need yet
