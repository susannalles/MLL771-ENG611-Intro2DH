Creating Your First Website and Setting Up a Work Environment in GitHub

Step 1: Building Your First Web Page Locally

The very first step is to understand how a website works. For this reason, I want you to download folder MLL771-ENG611-Intro2DH and work from your own computers. To make your first website you only need a single folder on your computer, one HTML files, and a browser. That is all a web page really is. Download this folder, and save it on your Desktop or another location you will easily find it.

What Is This Folder?

Think of your project as a folder or a small library that lives on your desk. Right now, only you can open it. Your browser is the reader — when you open an index.html file, the browser reads it and displays it as a page, exactly like opening a book. No internet needed. No server in the cloud. Just your computer talking to itself.

📁 my-first-website/
    ├── index.html  ← the structure and content
    └── style.css   ← the colors and fonts (optional for now because the instructions are in the HTML head)

How Does CSS Connect to HTML?

Look at the <head> section at the top of this file. You will find a <style> block — that is where the CSS lives inside the HTML itself. The browser reads the <head> first, learns the visual rules, and then applies them as it renders the <body>.

For example, the CSS rule h1 { color: #bd5734; } tells the browser: "every time you see an <h1> tag, make the text that warm reddish-brown." The rule body { background-color: #e6e2d3; } sets the sandy background you are reading on right now.

💡 Try it: Open this file in a text editor, change #bd5734 to blue inside the h1 rule, save, and refresh your browser. You just edited a live design.

Your Task for Step 1

Now it is your turn. In the STEP1 folder, open index.html in your text editor and make it your own. This is still just your private folder — nothing goes online yet. Experiment freely.

✏️ Before moving to Step 2, make sure you have:

  • Replaced the <title> with your own name or project title
  • Changed at least one color in the CSS (background, heading, or paragraph). A list of color codes.
  • Added at least two <h1> or <h2> headings with your own text
  • Written content inside the <p> paragraphs
  • Included at least one link using <a href="...">
  • Added at least one image using <img src="...">

Step 2: Publishing Your Website on GitHub Pages

Now that your website works locally, it is time to put it online so anyone can visit it. Think of what we did in Step 1 as writing in your private notebook — now we are going to place that notebook on a public shelf. The files do not change at all. We are simply moving them to a place the rest of the world can reach.

We will use GitHub Pages, a free service that turns a GitHub repository directly into a live website. GitHub is normally used by programmers to store and share code, but for our purposes it works perfectly as a simple web host — and it is free.

What you need to do

Follow these three steps in order:

  1. Create a GitHub account. Go to github.com and sign up. Choose your username carefully because it will become part of your website's permanent address. A name like firstnamelastname works well and looks professional.
  2. Create a new repository named exactly username.github.io, replacing username with the username you just chose. The name must match your username exactly, including lowercase letters — otherwise GitHub Pages will not activate.
  3. Upload your files from Step 1 to the repository. You can drag and drop them directly on GitHub for now. In a later step we will learn how to do this with GitHub Desktop from your computer.
  4. Activate GitHub Pages. Go to your repository's Settings → Pages (left menu). Under Branch, select main and click Save.

⏱ Wait a moment. After saving, GitHub takes 1–2 minutes to build your site. Then visit https://username.github.io and your website is live.

🌐 What just happened? GitHub read your index.html file and started serving it as a real website. The same file your browser was opening from your Desktop is now being opened by browsers anywhere in the world. The library moved from your desk to a public shelf.
